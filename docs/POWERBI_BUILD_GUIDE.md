# Power BI — build guide (fallback and walkthrough)

The PBIP in `powerbi/` is generated by `tools/build_powerbi.py`. If Power BI Desktop or Fabric rejects
the report layout or a TMDL property, for example because of a newer or older format version, build the
same thing by hand in about 30 minutes. Every DAX expression is in `docs/METRICS.md`.

## A. Semantic model (Fabric web, Direct Lake)

1. Open the lakehouse `lh_portfolio` and choose **New semantic model**. Name it `PortfolioPerformance` and tick these tables:
   `dim_date, dim_fund, dim_investor, dim_investment, dim_legal_entity, dim_report_currency, fact_commitment, fact_cashflow, fact_snapshot, fact_position, fact_accrual, fact_irr_flow, gold_nav_bridge, ops_dq_results, sec_user_investor, measure_table`.
2. **Open data model** and create these relationships. All are many-to-one, single direction:

| From (many) | To (one) |
|---|---|
| `fact_commitment`, `fact_cashflow`, `fact_snapshot`, `fact_irr_flow`, `gold_nav_bridge` `[fund_id]` | `dim_fund[fund_id]` |
| same five `[investor_id]` | `dim_investor[investor_id]` |
| same five `[legal_entity_id]` | `dim_legal_entity[legal_entity_id]` |
| `fact_position`, `fact_accrual`, `fact_irr_flow` `[investment_id]` | `dim_investment[investment_id]` |
| `fact_position`, `fact_accrual` `[fund_id]` | `dim_fund[fund_id]` |
| `fact_cashflow`, `fact_snapshot`, `fact_position`, `fact_accrual`, `gold_nav_bridge` `[date_key]` | `dim_date[date_key]` |
| `fact_irr_flow[as_of_date_key]` | `dim_date[date_key]` |

Leave `fact_commitment` unrelated to `dim_date`; the measures filter `commitment_date` themselves. Don't relate `dim_investment` → `dim_fund` or `dim_investor` → `dim_legal_entity`. Those links would create ambiguous paths, and the facts already carry both keys.

3. Model settings:
   * Mark `dim_date` as the date table on `date`.
   * Sort `dim_date[quarter_label]` by `quarter_sort`, and `gold_nav_bridge[component]` by `component_order`.
   * Hide every `*_id`, `*_key`, `fx_*` and `source_*` column, and hide the whole `fact_irr_flow` and `sec_user_investor` tables.
4. On `measure_table`, add the 26 measures from `METRICS.md`, keeping their names, display folders and format strings. Hide `id` and `note`; the table then shows as a measure table.
5. **Manage roles:**
   * `LP Investor`:
     * on `dim_investor`, the filter `dim_investor[investor_id] IN CALCULATETABLE ( VALUES ( sec_user_investor[investor_id] ), sec_user_investor[user_upn] = USERPRINCIPALNAME () )`;
     * on `sec_user_investor`, `[user_upn] = USERPRINCIPALNAME ()`;
     * on `ops_dq_results`, `FALSE ()`.
   * `Portfolio Team`: no filter.
6. **Settings → Refresh:** turn off *Keep your Direct Lake data up to date*. `nb_99_run_all` reframes the model after the quality gate.

## B. Report pages (1280 × 720)

Every page except Data Quality has a header with a title textbox, a card showing `[Report Title]`, and dropdown slicers on `dim_date[quarter_label]` and `dim_report_currency[currency_code]`.

| Page | Visuals |
|---|---|
| **Portfolio Overview** | Slicer `dim_fund[asset_class]`. 8 cards: Commitment, Paid In, Distributions, NAV, Unfunded, DPI, TVPI, Net IRR. Table: fund_name, asset_class, vintage_year, Commitment, Paid In, Distributions, NAV, DPI, TVPI, Net IRR. Clustered column chart: vintage_year × (Paid In, Distributions, NAV) |
| **Investor Performance** | Slicer `dim_investor[investor_name]`. Matrix with rows investor_name › fund_name and values Commitment, Paid In, Unfunded, Distributions, NAV, DPI, RVPI, TVPI, Net IRR |
| **NAV Bridge** | Slicers on fund_name and investor_name. **Waterfall chart**: Category `gold_nav_bridge[component]` (sort ascending by the category), Y `[Bridge Amount]`. The waterfall's total bar equals closing NAV. Table: component, Bridge Amount |
| **Investments** | Slicer asset_class. Cards: Cost Basis, Fair Value, Gross MOIC, Gross IRR, Principal Outstanding, Accrued Interest, Weighted Avg Coupon, Non-Performing %. Table: investment_name, fund_name, instrument, sector, country, Cost Basis, Fair Value, Mark to Cost, Gross MOIC, Gross IRR |
| **Data Quality** | Slicer `ops_dq_results[run_id]`. Cards: Checks Passed / Failed (latest run). Table: check_id, check_name, layer, severity, passed, failed_rows, detail, checked_at_utc |

## C. How to verify the numbers

For a quarter, currency and fund/investor you pick in the report, the values must match `gold_performance`:

```sql
SELECT grain, fund_id, investor_id, currency_code, paid_in, distributed, nav, dpi, tvpi, irr
FROM dbo.gold_performance
WHERE as_of_date = '2026-09-30' AND currency_code = 'USD' AND grain IN ('FUND_NET', 'PORTFOLIO_NET')
ORDER BY grain, fund_id;
```

The *Portfolio Overview* cards with no slicers in USD should equal the `PORTFOLIO_NET` row, and each fund row in the table should equal its `FUND_NET` row. `Net IRR` uses the same flows and the same ACT/365 XIRR, so it agrees to the displayed precision.
